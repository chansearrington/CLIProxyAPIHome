Where each change lives

Home decides. Nodes connect.

These are separate services with separate updates. The distinction matters when tracing an account choice or a request that bypasses the proxy.

01 / YOUR CLIENT

Claude Code & Codex

Your apps send requests to the local CPA endpoint. Codex’s default CPA provider and corrected CLI/daemon settings are preserved.

02 / LOCAL CPA NODE

The provider connection

The node obtains a dispatch decision from Home, translates the request, talks to the AI provider and reports usage back.

03 / CPA HOME

The shared control plane

Home stores credentials and settings, chooses an eligible account by the configured rules, distributes configuration and collects usage.

Home 1.1.0 embeds CPA SDK 8.0.4. Installing node 8.0.20 adds its newer request-handling fixes separately; it does not automatically replace Home’s scheduler or account-refresh implementation.

Carried forward

Your fleet behavior stays accounted for.

The upgrade integrates upstream changes into your fork. The fleet fixes and recovered account state are explicit preservation requirements.

Preserved in the fleet work

  • ✓Claude reset and account selection. Unified 5-hour and weekly reset handling, correct model/account error scope, warning handling and configured priorities.
  • ✓Existing credentials and access. Account identities, fresh authorizations, API keys, channel groups and Microsoft account isolation.
  • ✓Copilot behavior. Stable plugin OAuth identities, account-specific model discovery, quota collection and approved recollection behavior.
  • ✓Usage accounting and client routing. Existing accounting fixes and the live database’s pending-usage index; Codex defaults to the local CPA provider.

Additional fleet safeguards

Claude refresh safety. The fleet Home build ports a guard against immediately replaying a single-use refresh token after a transport, response-read or JSON failure.

This guard is separate from official Home 1.1.0. The investigation verified the defect, but did not prove it caused the original invalid Gmail authorization.

Safer SQLite configuration edits. A fleet safeguard serializes ordinary configuration edits to prevent concurrent writes from failing with a database-busy error. The regression test passed 50 repeated runs on the Ark, and its control reproduced the failure in the old code.

Separate dashboard reads from scheduler work. The tested patch gives usage queries a separate pool of up to four read-only SQLite connections. Dashboard reads no longer share the connection queue used by routing, node heartbeats and configuration writes. Four focused tests each passed 20 runs on the Ark; the full Go test suite also passed with the patch.

These database safeguards are tested and deployed. They are additions to the fleet fork, separate from official Home 1.1.0.

The account repair and Codex routing repair are recorded in the incident notes. The update does not replace those repairs.

Known dashboard limit. A seven-day Usage overview can still time out on this large database; this was confirmed with both the previous Home build and the upgraded build. The 24-hour panel load checks pass. The four separate readers keep dashboard queries out of the routing and heartbeat connection queue, but do not make every long-range report finish within its time limit.

Optional additions include weighted round-robin routing, extra Codex client controls, custom catalogs, Grok speech and a global GitHub token. New optional capabilities were not enabled by this rollout. They require the relevant configuration, route or provider.

Separate nonblocking findings remain tracked in issue #7, issue #8 and issue #9. Completing this rollout does not close those findings or the long-range dashboard limit.
