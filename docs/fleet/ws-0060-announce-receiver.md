# Scheduled-upgrade announcement receiver (build only)

Nothing here has been installed. Do not run these deployment steps without a separate approved operation. No Home policy, announcement URL, patch setting, node service, or production data was changed by this work.

## Contract

Home sends an HTTP POST with `Content-Type: application/json` and `Idempotency-Key` (a UUID). The JSON body contains `phase`, `target_version`, `window_start` (RFC3339), ordered `nodes` (UUIDs), and optional `reason` and `failed_nodes`. Supported phases: scheduled, reminder, started, done, rolled_back, rollback, rollback_failed, postponed. The receiver limits a body to 16 KiB and each node list to 100 entries. It rejects unknown fields and invalid values. A repeated key with an identical body is accepted without another journal entry; a different body is a conflict (409).

Home previously had no signature or custom authentication-header setting, and its API contract forbids URL credentials. The minimal addition reads `FLEET_ANNOUNCE_TOKEN` from Home's environment and sends `Authorization: Bearer …` when configured. The receiver requires the same private environment token and uses constant-time comparison on `/announce` (no query). The receiver requires at least 32 bytes; generate a high-entropy token, not a human password. No policy/schema field is added, so the secret never enters fleet state, Management responses, payloads or history. Existing third-party hooks remain compatible when Home's variable is absent; this receiver always refuses missing/wrong authentication. Never put the token in source control or command-line arguments, or enable request/header logging. No secret-file reader is included.

202 means **durably recorded on the Ark, waiting for delivery**, not read by an agent. Before every 2xx (including duplicate acceptance), the receiver flushes/fsyncs the mode-0600 JSONL journal and its containing directory. A write/sync failure is 503. Invalid authentication is 403, invalid payload is 400, wrong content type/transfer encoding is 415, oversize/empty body is 413. There is no GET API or HTTP acknowledgement endpoint. Pending reads and acknowledgements use the existing private SSH path, not another network service.

Home treats only 2xx as successful, never follows redirects, and uses a 20-second request timeout. It retries ordinary temporary failures after five minutes. Critical notices (done/rollback/rolled_back/rollback_failed) back off from five minutes up to one hour and survive expiry/ordinary queue caps. 408/429 and 5xx are temporary. Other 4xx now discard that notice with an `announcement / rejected_PHASE` audit event; they never create a rollback failure. Failed scheduled/reminder/started gates still postpone only their own window. Rejecting an old ordinary receipt no longer shifts unrelated windows. Other rollout-safety and fifteen-minute emergency rollback behavior is unchanged.

## Existing delivery path, reused

The ws-0056 model alert does **not** push from the Ark to an always-on Orchestrator endpoint. Its MacBook runner calls its `send('orchestrator', message)` helper, which resolves exactly one live `claude-code` terminal at `Hype | Orchestrator / 1` launched from `~/GitHub/hype-sports/hype`, then calls `hc send --json`. It refuses missing/ambiguous/wrong-folder terminals and never forces input.

`relay.py` imports that installed helper directly from `~/Library/Application Support/cpa-model-alert/alert.py`. It pulls the Ark's pending notices over the same ws-0056 SSH identity/options, builds one paragraph from validated status fields (never raw `reason` text), and acknowledges only an accepted send. It does not contact another chat platform, invent a message-board adapter, or send to the Home lead. No new package is needed.

The Ark remains always on and retains notices while the MacBook sleeps. **Orchestrator delivery pauses while the MacBook sleeps or the target terminal is unavailable.** A one-minute MacBook job resumes draining on wake. An accepted `hc` turn proves queued terminal input, not that anyone read or acted on it. A crash after a successful send but before the SSH acknowledgement can repeat a message; this deliberate at-least-once limit avoids losing a message. Only one relay instance runs at a time via a local file lock. Do not run a competing relay on another machine.

**Deployment blocker:** the existing Management webhook contract requires durable acceptance of both the Orchestrator message and Chanse's hosted review page before 2xx. This scoped build supplies durable logging and the Orchestrator outbox only. It does not create or durably queue the separate hosted review page. Do not configure this receiver as the live upgrade gate or enable upgrades until that second acceptance path is integrated and reviewed. A manually prepared page is not automatically a per-notice durable receipt. Force-now permissions and policy enabling remain outside this transport.

Copy only `receiver.py` into the code directory. Keep the journal on the direct `/mnt/cache` mount, not `/mnt/user`, and include it in configuration backups. Python 3.9+ is sufficient on Linux. 3. Have the operator supply `FLEET_ANNOUNCE_TOKEN` privately to a dedicated Unraid User Script wrapper (never add the wrapper or value to this repository). Start it at array startup using the existing Unraid service supervision process. Bind only the Ark's explicit Tailscale IPv4 address; the program refuses wildcard/public addresses. Do not publish the port on all interfaces or the internet. Use the tailnet's access rules and confirm Home's container can reach this address. Do not feed TEST data into production journals or real rollout state.

Only then, as a separate approved configuration operation, take the existing targeted policy backup and configure `announcement_url` as `http://100.110.133.6:8766/announce` without any secret. ## Inspect, stop, recover

- Private SSH command `python3 -I /mnt/cache/appdata/cpa-home/fleet-announce/receiver.py --pending` returns sanitized validated notice bodies and keys, not authentication. `--ack UUID` appends a durable sent receipt. Only the relay should acknowledge ordinary notices, after accepted delivery.
- Disable/boot out the MacBook `com.cpa-home.fleet-announce` launchd job first, then stop only the receiver's recorded process/service. Keep the JSONL journal and the ws-0056 installation. Do not clear Home's policy or enable/disable patch updates as an incidental cleanup.
- `announcements.jsonl` is the dedupe record **and** outbox. Do not rotate, truncate or delete it during operation. Announcement volume is small; this minimal implementation replays the journal per transaction. If volume grows, replace replay with an indexed durable outbox before adding log rotation.
- Corrupt/incomplete journals fail closed; the HTTP receiver returns 503 and the CLI exits nonzero rather than forgetting delivery history. Stop the receiver, preserve the damaged journal, and have the operator restore/reconcile the last complete records from backup before restart. Never silently delete a partial line or accept new notices over corruption.
- Keep executable directories and journal writable only by the service operator. The SSH account is already privileged; this change does not broaden it. Review a least-privilege SSH wrapper separately if that identity is ever replaced.
